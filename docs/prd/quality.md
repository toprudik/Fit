# Планка качества и Definition of Done

Источник: [`docs/decisions.md`](../decisions.md) (Q14, Q43, Q26, Q38, Q41, Q44, Q12/Q27/Q36), [ADR 0002](../adr/0002-secrets-handling.md), [ADR 0004](../adr/0004-telegram-auth.md). Действует для каждой фичи каждой волны.

**Черта качества 17.11.2026**: фича, не прошедшая этот документ целиком, не выкатывается в бету 24.11 и переносится в декабрьскую волну. Частичного «выкатим, потом доделаем» нет.

## 1. Производительность

| Метрика | Порог | Как проверяем |
|---|---|---|
| Открытие Mini App до интерактивного первого экрана | **< 1,5 с** на среднем Android (допущение: класс Moto G Power / Galaxy A-серии, 4G) | Lighthouse mobile с троттлингом + замер на реальном устройстве перед релизом волны |
| Lighthouse (Performance, Accessibility, Best Practices, SEO) | **≥ 90** каждая, mobile | Lighthouse CI на ключевых страницах в PR (допущение) |
| LCP / INP / CLS | ≤ 2,5 с / ≤ 200 мс / ≤ 0,1 (допущение, p75) | Vercel Speed Insights / web-vitals |
| JS первого экрана | ≤ 170 КБ gzip (допущение) | отчёт сборки |
| Ответ API на чтение | p95 ≤ 300 мс (допущение) | логи / Sentry performance |
| Анимации и скролл | **60 fps** | DevTools Performance на среднем Android |

## 2. Дизайн и ощущение «суперапп» (Q14/Q43)

1. Фирменный дизайн везде, включая Mini App; ориентиры — Apple Fitness, Whoop.
2. **Фиксированный нижний таб-бар и шапка**; контент скроллится между ними.
3. **Нативные переходы** между экранами (push/pop, модальные листы снизу), жест «назад»; в Telegram — `BackButton` синхронизирован с навигацией.
4. **Haptics в Telegram** (`HapticFeedback`): impact на нажатия ключевых кнопок, notification success/error на результат действий, selection на переключатели (допущение по маппингу).
5. **Safe areas**: учтены `env(safe-area-inset-*)` и safe area Telegram (контент и таб-бар не перекрываются вырезом, home indicator, шапкой Telegram); полноэкранный режим Mini App — с content safe area.
6. **Темы**: тёмная и светлая, автоматически по системе / `colorScheme` Telegram + ручной переключатель; каждый экран проверен в обеих.
7. **Адаптивность**: от **360 px** до десктопа без горизонтального скролла; на десктопе — адаптированная раскладка, а не растянутый мобильный экран (допущение).
8. **Анимации**: премиальные, детальные (`motion/react`), **60 fps**; при `prefers-reduced-motion` — без движения/параллакса, только мгновенные или fade-переходы.
9. Состояния каждого экрана: загрузка (скелетоны), пусто (с действием), ошибка (с повтором), офлайн (допущение: баннер «Нет сети», без падения).

## 3. Доступность — WCAG 2.2 AA

1. Контраст текста ≥ 4,5:1 (крупный ≥ 3:1), элементов интерфейса ≥ 3:1 — в обеих темах.
2. Цели касания ≥ 24×24 CSS px (2.5.8), для основных действий — 44×44 (допущение).
3. Полная работа с клавиатуры на вебе, видимый фокус, фокус не скрыт таб-баром/шапкой (2.4.11).
4. Скринридеры: семантическая разметка, подписи у иконок-кнопок, `aria-live` для тостов и результатов.
5. Не только цвет передаёт смысл (графики, статусы, кольца прогресса).
6. Масштаб текста до 200% без потери функций.
7. Перетаскивание всегда имеет альтернативу (2.5.7).
8. Проверка: axe в e2e на ключевых экранах без нарушений уровня A/AA + ручная проверка VoiceOver/TalkBack перед релизом волны (допущение).

## 4. Языки (Q5)

1. RU + EN, по умолчанию RU; автоопределение по языку устройства / Telegram `language_code`; ручной переключатель.
2. Нет захардкоженных строк; все строки, включая сообщения бота, ошибки и CSV-заголовки, — в словарях.
3. Даты, числа, валюты, единицы — по локали (`Intl`); плюрализация по правилам языка.
4. Каждый экран проверен на обоих языках, длинные EN/RU строки не ломают раскладку.

## 5. Тесты

| Уровень | Что обязательно | Инструмент (допущение) |
|---|---|---|
| Unit | **Все бизнес-правила** фичи: списания и отмены, долги, абонементы, калькулятор нормы, попадание в норму, аналитика и финансы, серии, бонусы после оплаты, корзины расстояний и т. п. Каждый числовой пример из критериев приёмки PRD — тест. | Vitest |
| E2E | **Ключевые сценарии** фичи по критериям приёмки: тренер и клиент, Mini App-окружение и веб, 360 px и десктоп. | Playwright |
| RLS-изоляция | Для каждой новой таблицы: тренер A не видит данных тренера B; тренер без **разрешения на данные** не видит соответствующих данных клиента; клиент не видит чужих данных; админ не видит личных данных клиента; делегат видит только делегированное. | тесты против локального Supabase |
| Бот | Хендлеры и формат сообщений. | pytest |
| Контракт | Ответы API для админа не содержат личных полей клиента. | unit/интеграционные |

Правило: баг в бизнес-правиле исправляется вместе с тестом, воспроизводящим его.

## 6. Наблюдаемость

1. **Sentry** на вебе (клиент + сервер) и в боте; релизы и source maps; окружения разделены.
2. В событиях Sentry нет ПДн и секретов: без `initData`, токенов, значений питания/замеров, текстов заметок; пользователь идентифицируется внутренним id (допущение).
3. Новая ошибка в проде, затрагивающая ≥ 1% сессий, — блокер (допущение).

## 7. Безопасность

По [ADR 0002](../adr/0002-secrets-handling.md) и [ADR 0004](../adr/0004-telegram-auth.md):
1. Секреты только в env; новая переменная — в `.env.example` с пометкой public / server-only; server-only читаются только через `src/env/server.ts`.
2. `NEXT_PUBLIC_*` — только безопасные для браузера значения.
3. Отдельные ключи и боты для local / preview / production.
4. Вход только через Telegram: проверенный `initData` (HMAC, возраст ≤ `TELEGRAM_INIT_DATA_MAX_AGE`) или OIDC; `initDataUnsafe` и присланные клиентом id не доверяются.
5. Supabase secret key — только там, где RLS нужно обойти; никогда для отдачи данных пользователю.
6. RLS на каждой открытой таблице; схема только миграциями; после DDL — Supabase security advisors без предупреждений уровня ERROR/WARN (допущение для WARN).
7. Вебхуки аутентифицированы (`X-Telegram-Bot-Api-Secret-Token`, подписи провайдеров); новые публичные эндпоинты с токенами (iOS Shortcuts и т. п.) — с хешированием токенов и rate limit.
8. Gitleaks в CI зелёный.
9. Мутации — серверные действия/роуты с проверкой прав на сервере, same-origin для POST.

## 8. Приватность

1. Тренер видит только свои **пары** и только разрешённые клиентом данные (Q38); фото — только по явному разрешению; заметки тренера по умолчанию скрыты от клиента.
2. Админ не видит питание, фото, замеры, анкету, активность без логируемого аварийного доступа (Q41).
3. Новые данные фичи включены в **экспорт** и удаляются при **удалении аккаунта** (30 дней) (Q44).
4. Фото: размытие лица на устройстве до загрузки, приватное хранилище, временные ссылки (Q24/Q30/Q35).
5. Точная геопозиция пользователя не хранится (Q49, Q52).
6. Данные тела/питания/фото прогресса не публикуются автоматически никуда (Q48).
7. Минимизация: собираем только то, что нужно фиче; новые категории данных — с обновлением бета-согласия (допущение).
8. Атрибуция внешних данных: wger (CC-BY-SA), Open Food Facts (ODbL), OpenStreetMap/OpenFreeMap.

## 9. Definition of Done (чеклист фичи)

- [ ] Все критерии приёмки из PRD выполнены и проверены.
- [ ] Unit-тесты на все бизнес-правила, e2e на ключевые сценарии, RLS-тесты на новые таблицы.
- [ ] Веб: `npm run lint && npm run typecheck && npm test && npm run build` зелёные; бот: `uv run ruff check . && uv run ruff format --check . && uv run pytest` зелёные.
- [ ] Миграции в `supabase/migrations/`, RLS включён, security advisors чистые.
- [ ] Бюджеты производительности и Lighthouse ≥ 90 соблюдены.
- [ ] WCAG 2.2 AA: axe без нарушений, ручная проверка скринридером.
- [ ] Проверено: 360 px, планшет, десктоп; обе темы; RU и EN; Mini App (iOS + Android) и веб.
- [ ] Таб-бар и шапка, нативные переходы, `BackButton`, haptics, safe areas работают.
- [ ] 60 fps; reduced motion соблюдён.
- [ ] Состояния загрузки/пусто/ошибка/офлайн.
- [ ] Sentry подключён, ПДн и секреты не попадают в события и логи.
- [ ] Новые env в `.env.example`; секреты не в коде.
- [ ] Новые данные — в экспорте и удалении аккаунта; разрешения на данные соблюдены.
- [ ] Уведомления бота — с типом, отключаемые, уважают тихие часы.
- [ ] Термины интерфейса и кода соответствуют `CONTEXT.md`.
- [ ] Продуктовая приёмка: Давид или Sam прошли сценарий на реальном устройстве (допущение).

## 10. Связь с метриками беты (Q26)

Каждая фича должна быть измеримой для метрик беты: события «занятие изменено вручную», «открытие из напоминания», использование функции — логируются без ПДн (допущение). Цели беты: ≥ 4 из 5 тренеров ведут всё расписание 2 недели подряд; 80% занятий без ручных правок; клиенты открывают приложение из напоминаний; NPS тренеров ≥ 50.

## Допущения

1. Эталон «среднего Android» — класс Moto G Power / Galaxy A, 4G.
2. Lighthouse CI в PR; ≥ 90 по всем четырём категориям, mobile.
3. Web Vitals: LCP ≤ 2,5 с, INP ≤ 200 мс, CLS ≤ 0,1 (p75).
4. JS первого экрана ≤ 170 КБ gzip; p95 API-чтения ≤ 300 мс.
5. Маппинг haptics по типам действий.
6. Десктоп — отдельная адаптированная раскладка.
7. Офлайн-состояние: баннер без падения, без офлайн-режима записи.
8. Цели касания основных действий 44×44.
9. Ручная проверка VoiceOver/TalkBack перед релизом каждой волны.
10. Инструменты: Vitest, Playwright, pytest, тесты RLS на локальном Supabase.
11. В Sentry пользователь — по внутреннему id, без ПДн; порог блокера ≥ 1% сессий.
12. Security advisors: без ERROR и WARN.
13. Новые категории данных требуют обновления бета-согласия.
14. Продуктовая приёмка на реальном устройстве Давидом или Sam.
15. События метрик беты логируются без ПДн.
