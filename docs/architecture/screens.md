# DaFit — карта экранов и информационная архитектура

Источники: [`docs/decisions.md`](../decisions.md) (первоисточник), [`CONTEXT.md`](../../CONTEXT.md) (термины), [`docs/prd/README.md`](../prd/README.md) (волны), [`docs/adr/0004-telegram-auth.md`](../adr/0004-telegram-auth.md) (вход).
Термины ниже — строго из глоссария. Маршруты — пути Next.js App Router в `apps/web`; один и тот же маршрут работает на сайте и в Mini App. Волна у экрана — волна, в которой он появляется впервые; поздние вкладки/секции внутри экрана помечены отдельно (например, «Питание — В2»).

## 1. Оболочка приложения («суперапп»)

### 1.1. Каркас и адаптивность

| Ширина окна | Навигация | Детальные экраны | Модальные |
|---|---|---|---|
| < 768 px (телефон, Mini App на телефоне) | Фиксированный **нижний таб-бар** (≤ 5 вкладок) | Push-экран на всю ширину | Bottom sheet (шторка снизу) |
| 768–1279 px (планшет, узкое окно Telegram Desktop) | **Боковая навигация** свёрнутая (иконки) | Push-экран | Центрированный диалог |
| ≥ 1280 px (десктоп) | Боковая навигация развёрнутая (иконки + подписи) | **Master–detail**: список слева, деталь справа (клиенты, занятия, оплаты) | Центрированный диалог; формы создания — боковая панель справа |

- Режим выбирается **по ширине окна, а не по платформе**: Mini App в широком окне Telegram Desktop получает боковую навигацию.
- Минимальная ширина — 360 px. Все экраны работают в обеих темах и на RU/EN.

### 1.2. Шапка (header)

- Фиксированная, полупрозрачная с размытием фона. На корневых экранах вкладок — **крупный заголовок**, который при прокрутке сворачивается в компактный (как в iOS).
- Слева: на корне вкладки — **аватар** (открывает «Профиль»: переключатель зон, настройки, обратная связь); на push-экране — «Назад» (только на сайте; в Telegram вместо неё нативная `BackButton`).
- Справа: **до 2 контекстных действий** экрана (например, «+» новое занятие, фильтр, поделиться). Остальное — в меню «⋯».
- Подзаголовок — контекст: дата в календаре, имя клиента в карточке пары, «на проверке» у неверифицированного тренера.
- На десктопе шапка содержит хлебные крошки (`Клиенты / Анна К. / Абонементы`) и действия; аватар и переключатель зон — вверху боковой навигации.

### 1.3. Переходы

| Переход | Анимация (`motion/react`) | Когда |
|---|---|---|
| Push / pop | Новый экран въезжает справа, предыдущий сдвигается на ~30% с затемнением (параллакс iOS); pop — обратно. Свайп от левого края = назад (только сайт; в Telegram жест забирает клиент). | Вглубь иерархии: список → деталь → редактирование |
| Модальный | Шторка снизу с «ручкой», закрытие свайпом вниз; на десктопе — диалог с fade + scale 0.96→1 | Создание, подтверждение, выбор, короткие формы |
| Смена вкладки | Мгновенно, без сдвига, лёгкий crossfade не дольше `duration-fast` (160 мс). **Каждая вкладка хранит свой стек и позицию прокрутки.** Повторный тап по активной вкладке — к корню вкладки / вверх. | Таб-бар, боковая навигация |
| Смена зоны | Короткий crossfade всего каркаса, таб-бар перестраивается | Переключатель зон |
| Общие элементы | Shared-layout: аватар клиента из списка «перелетает» в шапку карточки; карточка занятия раскрывается в экран занятия | Список → деталь |

- `prefers-reduced-motion` → все переходы заменяются на fade ≤ 100 мс, параллакс и пружины отключаются.
- Цель — 60 fps на среднем Android: анимируются только `transform` и `opacity`.
- Скелетоны вместо спиннеров; данные экрана подгружаются при наведении/видимости ссылки (prefetch), чтобы push ощущался мгновенным.

### 1.4. Safe areas

- Сайт: `viewport-fit=cover`, отступы из `env(safe-area-inset-*)`.
- Mini App: значения `safeAreaInset` и `contentSafeAreaInset` из Telegram (Bot API 8.0+) пробрасываются в CSS-переменные; контент не залезает под системную шапку Telegram, «чёлку» и home indicator.
- Таб-бар = высота 56 px + нижний inset; плавающие кнопки и шторки учитывают таб-бар и клавиатуру (`viewportStableHeight` в Mini App, `visualViewport` на сайте).

### 1.5. Telegram Mini App: нативные элементы

| Элемент | Правило |
|---|---|
| Старт | `ready()` после первого кадра (splash в цвете фона), `expand()`; цвета шапки/фона/нижней панели Telegram (`setHeaderColor`, `setBackgroundColor`, `setBottomBarColor`) = токены текущей темы DaFit. Тёмная/светлая — по `colorScheme` Telegram, если пользователь не выбрал тему вручную. |
| `BackButton` | Показана на любом push-экране и в открытой шторке; скрыта на корнях вкладок. Нажатие = pop / закрыть шторку. |
| `MainButton` | Главное действие экрана-формы или шага потока: «Сохранить», «Записаться», «Отправить запрос», «Отметить оплату», «Далее». Состояния: неактивна (форма невалидна), прогресс (идёт запрос). На сайте тот же компонент рисует **липкую CTA-кнопку** над таб-баром. На экранах с MainButton таб-бар скрыт. |
| `SecondaryButton` | Второе действие рядом с главной («Перенести» рядом с «Отменить», «Пропустить» в мастере). |
| Haptics | `impactOccurred('light')` — смена вкладки, тап по карточке; `selectionChanged()` — пикеры даты/времени, переключатели, свайп по календарю; `notificationOccurred('success' / 'warning' / 'error')` — запись подтверждена, оплата отмечена / списание, поздняя отмена / ошибка. На сайте — `navigator.vibrate`, где есть, иначе ничего. |
| `enableClosingConfirmation` | Включается, пока в форме есть несохранённые изменения. |
| `disableVerticalSwipes` | На экранах с вертикальными жестами (календарь, кисть размытия, шторки). |
| `SettingsButton` | В меню «⋯» Telegram → `/settings`. |
| `showScanQrPopup` | «Введите код тренера» → «Сканировать QR»; чек-ин по QR (В3). |
| `requestWriteAccess` | В онбординге, если пользователь пришёл по прямой ссылке Mini App и не запускал бота: без этого бот не сможет присылать уведомления. |
| `requestContact` | «Попросить связаться» — пользователь явно делится контактом, бот пересылает его собеседнику. |
| `openTelegramLink` | Кнопка «Написать» → `t.me/<username>` собеседника. |
| `shareURL` / `switchInlineQuery` | Поделиться витриной, ссылкой клиента, ссылкой на пробное, карточкой для сторис (В3). |
| `addToHomeScreen` | Предложение после первой успешной записи / первого занятия. |

### 1.6. Зоны и переключатель

- Маршруты зон: `/trainer/*` и `/client/*`. Зона определяется **префиксом пути**, поэтому любая ссылка однозначно открывает нужную зону.
- `/` → редирект в **последнюю открытую зону** (хранится в профиле на сервере, чтобы совпадать между сайтом и Mini App). Новый пользователь без зон → онбординг.
- Переключатель: сегмент «Тренер | Клиент» в «Профиле» (аватар в шапке) и вверху боковой навигации на десктопе. Переход по уведомлению или deep link сразу переключает зону и запоминает её как последнюю.
- **Только клиент** (нет профиля тренера): переключателя нет нигде, аватар открывает обычный профиль; `/trainer/*` редиректит в `/client`. В «Профиле» есть неброский пункт «У меня есть инвайт тренера» → ввод кода.
- **Тренер без собственных пар-клиентов**: переключатель виден, зона «Клиент» открывается с пустым состоянием «Вы пока не занимаетесь у тренера → Ввести код тренера».
- **Админ**: не зона, а раздел `/admin` — пункт «Админка» в «Профиле» и в боковой навигации, виден только админам.
- Акцент зоны: у каждой зоны свой акцентный цвет в пределах фирменной палитры и подпись в шапке «Профиль», чтобы тренер-клиент всегда понимал, где он.

### 1.7. Deep links

**Прямые ссылки Mini App**: `https://t.me/fitconnection_bot?startapp=<param>` (главная Mini App бота). Параметр — `[A-Za-z0-9_-]`, ≤ 512 символов. Формат: `<ключ>_<id>`; id — UUID (дефисы допустимы) или код.

| `startapp` | Открывает | Зона |
|---|---|---|
| `ti_<code>` | Погашение инвайта тренера → мастер профиля | — (онбординг) |
| `ci_<code>` | Лендинг ссылки клиента `/i/<code>` | Клиент |
| `tl_<code>` | Лендинг ссылки на пробное `/trial/<code>` | Клиент |
| `tp_<slug>` | Витрина тренера `/trainers/<slug>` | Клиент |
| `t_today` | `/trainer` | Тренер |
| `t_session_<id>` | `/trainer/sessions/<id>` | Тренер |
| `t_request_<bookingId>` | `/trainer/requests/<bookingId>` | Тренер |
| `t_client_<coachingId>` | `/trainer/clients/<coachingId>` | Тренер |
| `t_claim_<claimId>` | `/trainer/clients/claims/<claimId>` | Тренер |
| `t_pay_<coachingId>` | `/trainer/clients/<coachingId>/payments?action=new` | Тренер |
| `c_home` | `/client` | Клиент |
| `c_booking_<bookingId>` | `/client/bookings/<bookingId>` | Клиент |
| `c_pass_<passId>` | `/client/passes/<passId>` | Клиент |
| `c_book_<coachingId>` | `/client/book?coaching=<coachingId>` | Клиент |

- Неизвестный ключ или чужой id (RLS не вернул данных) → корень зоны + тост «Нет доступа или ссылка устарела». Никаких данных из параметра не показывается до проверки на сервере.
- **Кнопки бота** в уведомлениях — inline-кнопки `web_app` с полным URL маршрута (`https://<host>/trainer/sessions/<id>?action=waive`): Mini App открывается сразу на нужном экране в нужной зоне, `initData` приходит как обычно. Бот не выполняет действий сам — кнопка «Простить» открывает экран с предоткрытой шторкой прощения.
- **На сайте** те же пути работают как обычные URL; без сессии — `/login?next=<путь>` (редирект только на свой origin, см. ADR 0004).
- **QR-коды** (витрина, ссылка клиента) кодируют веб-URL (`https://<host>/i/<code>`), а не `t.me`: так QR открывается любой камерой, лендинг показывает превью тренера и предлагает «Открыть в Telegram» (основная кнопка → `startapp=ci_<code>`) или «Войти на сайте».

### 1.8. Общие паттерны экранов

- **Пустые состояния**: иллюстрация + одна фраза + одно главное действие. Никогда не пустой белый экран.
- **Pull-to-refresh** на списках; оптимистичные обновления с откатом и тостом при ошибке.
- **Офлайн/ошибка сети**: баннер под шапкой, формы не теряют ввод.
- **Обратная связь**: пункт «Сообщить о проблеме / идея» в «Профиле» обеих зон (`/feedback`, шторка, прикрепляет маршрут и версию).
- **Связь с человеком** везде, где есть собеседник: «Написать» (Telegram-чат) или «Попросить связаться», если нет юзернейма.

## 2. Навигация по зонам

### 2.1. Зона «Тренер» — таб-бар

| # | Вкладка | Маршрут | Что внутри |
|---|---|---|---|
| 1 | **Сегодня** | `/trainer` | Занятия на сегодня (таймлайн), запросы на запись, долги и заканчивающиеся абонементы, дни рождения/вехи клиентов, быстрые действия. Баннер «на проверке» до верификации. |
| 2 | **Расписание** | `/trainer/schedule` | Календарь день/неделя, занятия, слоты, шаблон недели, лист ожидания (В2). |
| 3 | **Клиенты** | `/trainer/clients` | Список пар, карточка пары со всеми вкладками, группы (В2) — сегментом вверху списка. |
| 4 | **Деньги** | `/trainer/money` | Оплаты, долги, абонементы всех клиентов, пакеты и ценовая сетка; финансы и симулятор цен (В2). |
| 5 | **Ещё** | `/trainer/more` | Витрина и QR, ссылки (клиента/пробное), аналитика (В2), отзывы (В2), команда/делегирование (В3), реферальные акции (В3), сообщество (В4), уведомления, настройки тренера. |

Главное глобальное действие «+» в шапке вкладок 1–2: «Занятие», «Слот», «Клиент (ссылка/QR)», «Добавить клиента вручную», «Оплата».

### 2.2. Зона «Клиент» — таб-бар

| # | Вкладка | Маршрут | Что внутри |
|---|---|---|---|
| 1 | **Главная** | `/client` | Ближайшее занятие, остаток абонемента, цели на сегодня (норма, шаги, ДЗ), быстрый ввод (вес, еда, шаги). |
| 2 | **Занятия** | `/client/sessions` | Предстоящие и прошедшие записи, «Записаться», запросы, домашние задания (В2). |
| 3 | **Дневник** | `/client/diary` | В1: тренировки (свои логи и логи с занятий). В2: питание, активность (шаги, вода, сон). Переключатель дней сверху. |
| 4 | **Прогресс** | `/client/progress` | Замеры и графики, фото прогресса и «до/после», рекорды, вехи; достижения (В3), месячный отчёт (В3). |
| 5 | **Тренеры** → **Сообщество** (В4) | `/client/trainers` → `/community` | В1–3: мои тренеры, абонементы, оплата, разрешения на данные. В4 вкладку занимает «Сообщество» (лента, бадди, карта, каталог), а «Мои тренеры» переезжают в «Профиль» и в карточки на «Главной». |

Если у клиента один тренер, «Тренеры» сразу открывает карточку этого тренера (без списка из одного элемента).

### 2.3. Профиль (обе зоны, по аватару)

Шторка/экран `/profile`: имя и фото из Telegram, **переключатель зон** (если есть обе), «Настройки» (`/settings`), «Админка» (только админ), «Сообщить о проблеме», «У меня есть инвайт тренера» (только клиент), в В4 — «Моя стена».

### 2.4. Админ-раздел (desktop-first)

`/admin` — отдельный каркас: всегда боковая навигация, плотные таблицы с фильтрами и поиском; на телефоне — работает, но списком без master–detail. Пункты: Обзор беты · Инвайты · Верификация · Пользователи · Обратная связь · Отзывы и споры (В2) · Жалобы (В2/В4) · Аналитика (В2) · Клубы (В4) · Модерация ленты (В4) · Журнал действий. Экрана аварийного доступа в бете нет: это логируемая серверная функция без интерфейса (ADR 0007); её вызовы видны в «Журнале действий».

## 4. Ключевые пользовательские потоки

### 4.1. Тренер: онбординг → первый клиент

1. Админ в `/admin/invites` создаёт инвайт тренера и отправляет ссылку `t.me/fitconnection_bot?startapp=ti_<code>`.
2. Тренер открывает ссылку → Mini App, splash, автовход по `initData`.
3. `/onboarding/consent` → «Принимаю».
4. `/onboarding/preferences`: язык и тема уже определены, разрешение писать от бота (`requestWriteAccess`) → «Далее».
5. `/onboarding/trainer?code=` — код действителен → «Стать тренером».
6. Мастер `/onboarding/trainer/[step]`: имя/фото → специализации и формат → локация → часовой пояс и валюта → дедлайн отмены (24 ч) → ссылка на оплату → ценовая сетка из шаблона → сертификаты (или «Позже»). MainButton «Далее», SecondaryButton «Пропустить».
7. `/onboarding/trainer/done`: превью витрины, QR, статус «на проверке» (работать можно сразу) → «Поделиться ссылкой клиента» (`shareURL`) или показать QR в полноэкранном режиме.
8. Клиент проходит поток 4.2. Тренеру приходит сообщение бота «Новый клиент: Анна К.» с кнопкой `web_app` → `/trainer/clients/<coachingId>`.
9. В карточке пары тренер жмёт «Занятие» → `/trainer/sessions/new` с предзаполненным клиентом → время, локация, повтор пн/ср/пт → MainButton «Назначить» → haptic success, клиенту уходит уведомление.

### 4.2. Клиент: вход по QR и запись

1. Клиент сканирует QR камерой телефона → `https://<host>/i/<code>`: карточка тренера.
2. «Открыть в Telegram» → `startapp=ci_<code>` → Mini App открывает `/i/<code>`, автовход.
3. Бета-согласие → язык/тема (автоопределены; `requestWriteAccess`).
4. Пара создаётся без подтверждения тренера → тост «Вы занимаетесь у Ивана» + haptic success. Если у тренера есть карточки клиентов без аккаунта, тренеру приходит «Это <Имя>?» (`t_claim_…`); после его подтверждения история карточки появляется у клиента.
4a. Шаг согласия на анкету `/client/trainers/<coachingId>/intake-consent`: «Показать» / «Не показывать».
5. Анкета `/client/trainers/<coachingId>/intake` (цели, здоровье, травмы, PAR-Q) → «Отправить тренеру» (или «Позже»).
6. `/client` → «Записаться» → `/client/book?coaching=<id>`: лента дней, слоты.
7. Выбор слота → шторка подтверждения:
   - есть активный абонемент → «Останется 7 занятий», MainButton «Записаться» → запись подтверждена сразу;
   - нет абонемента → «Это запрос на запись. Разовое — 2 000 ₽», ссылка на оплату тренера, MainButton «Отправить запрос».
8. При запросе: тренер получает уведомление → `/trainer/requests/<bookingId>` → «Подтвердить» → клиенту приходит «Запись подтверждена» с кнопкой → `/client/bookings/<bookingId>`.
9. Напоминания по настройкам (по умолчанию — значения тренера).

### 4.3. Поздняя отмена и списание

1. Клиент на `/client/bookings/<id>` жмёт «Отменить». До занятия 5 ч, дедлайн 24 ч.
2. Шторка: «Бесплатная отмена была до вт 10:00. Будет списано 1 занятие из «10 занятий» (останется 6)». «Перенести» после дедлайна недоступно — с подсказкой «Напишите тренеру».
3. Выбор причины (болезнь, работа, другое + текст) → MainButton деструктивная «Отменить со списанием» → haptic warning.
4. Создаётся списание с причиной; запись в истории — «поздняя отмена». Если остатка нет, списание уходит в долг.
5. Тренер получает уведомление «Анна отменила за 5 ч — списано 1 занятие» с кнопками «Открыть» и «Простить» (`web_app` → `/trainer/sessions/<id>?action=waive&booking=<id>`).
6. «Простить» → шторка с комментарием → MainButton «Простить» → прощение, остаток +1 (или долг −1), haptic success.
7. Клиенту: «Иван простил списание, остаток 7». В истории абонемента обе записи видны с причинами.
8. Неявка: тренер на экране занятия отмечает «Неявка» → то же списание и тот же путь прощения.

### 4.4. Фото прогресса с размытием лица

1. `/client/progress/photos` → «+ Фото» → `/client/progress/photos/new`.
2. Ракурс: спереди / сбоку / сзади (подсказка позы и прошлое фото этого ракурса полупрозрачно для совмещения).
3. Камера или галерея. Фото не покидает устройство.
4. На устройстве: детекция лица → автоматическое размытие с запасом по контуру; EXIF и геометки удаляются.
5. Экран проверки: увеличенный предпросмотр, кисть «Размыть» / «Стереть размытие», размер кисти; `disableVerticalSwipes`. Если лицо не найдено — предупреждение «Лицо не найдено — проверьте сами» и MainButton заблокирована, пока пользователь не подтвердит галочкой «Лица не видно».
6. MainButton «Лицо скрыто, сохранить» → загружается **только размытая версия** в приватное хранилище.
7. Шторка «Кому показать?»: список тренеров, у которых фото закрыто (по умолчанию все выключены) → включить для нужных или «Только мне».
8. Фото в галерее; если есть ≥ 2 одного ракурса — предложение «Сравнить до/после» → `/client/progress/compare`. Тренер видит фото только по временным ссылкам и только при разрешении.

### 4.5. Тренер отмечает оплату, долг гасится

1. Тренеру приходит утренняя сводка: «У Анны долг 2 занятия» → кнопка → `/trainer/clients/<coachingId>`.
2. Обзор пары: плашка «Долг: 2 занятия» → «Отметить оплату» → шторка `?action=new`.
3. Выбор: «Пакет 10 занятий» (сумма и валюта подставлены из сетки), способ (СБП/наличные/перевод), дата (сегодня).
4. Предпросмотр: «Будет создан абонемент на 10 занятий. Долг 2 занятия будет погашен из него — останется 8».
5. MainButton «Отметить оплату» → haptic success, оплата и абонемент созданы, долг закрыт.
6. Плашка долга исчезает с анимацией, остаток 8/10; запись появляется в «Деньги → Оплаты».
7. Клиенту бот: «Оплата 18 000 ₽ отмечена. Абонемент: 8 из 10» → кнопка → `/client/passes/<passId>`.
8. Вариант без пакета: «Погашение долга» — сумма = 2 × цена разового, долг обнуляется без нового абонемента.

## 5. Допущения

Места, где `decisions.md` молчит; приняты для карты экранов, пересматриваются через журнал решений.

1. **Маршруты зон** — префиксы `/trainer/*`, `/client/*`, `/admin/*`; общее — `/settings`, `/profile`, `/onboarding`; публичное — `/trainers/[slug]`, `/i/[code]`, `/trial/[code]`, `/join`; сообщество — `/community/*`, `/u/[handle]`.
2. **Карточка пары адресуется id пары** (`coachingId`), а не id пользователя: все данные пары изолированы, и у клиента с двумя тренерами две разные карточки.
3. **Профиль открывается по аватару в шапке**, переключатель зон — там же (и в боковой навигации на десктопе); отдельной вкладки «Профиль» нет, чтобы уложиться в 5 вкладок.
4. **Таб-бары**: тренер — Сегодня / Расписание / Клиенты / Деньги / Ещё; клиент — Главная / Занятия / Дневник / Прогресс / Тренеры. В волне 4 у клиента 5-я вкладка становится «Сообщество», «Мои тренеры» переезжают в «Профиль» и на «Главную»; у тренера сообщество — в «Ещё».
5. В волне 1 вкладка клиента «Дневник» содержит только тренировки; питание и активность добавляются в волне 2.
6. **Переключатель зон виден тренеру всегда** (зона «Клиент» с пустым состоянием); клиенту без профиля тренера — никогда. Админка — раздел, а не третья зона.
7. **Последняя зона хранится на сервере** (в профиле), а не в `localStorage`/CloudStorage, чтобы совпадать между сайтом и Mini App.
8. **Грамматика `startapp`**: `<ключ>_<id>`; ключи `ti`, `ci`, `tl`, `tp`, `t_*`, `c_*` из таблицы §1.7. Кнопки бота — `web_app` с полным URL маршрута.
9. **QR кодирует веб-URL** с лендингом и кнопкой «Открыть в Telegram», а не прямую `t.me`-ссылку.
10. **Оформление внутри Telegram**: фирменная палитра DaFit, светлая/тёмная — по `colorScheme` Telegram (если не выбрана вручную); цвета шапки/фона Telegram выставляются из наших токенов. `--tg-theme-*` используются как запасной вариант и для системных элементов, а не как основная палитра.
11. **Режим навигации выбирается по ширине окна** (< 768 — таб-бар, ≥ 768 — боковая навигация, ≥ 1280 — master–detail), а не по платформе.
12. **Перенос после дедлайна клиенту недоступен** (только отмена со списанием или «Написать тренеру»); тренер переносит без ограничений и без списания.
13. **Списание при нулевом остатке всегда уходит в долг** (Q22). Переключатель «Разрешить запись в долг» — в карточке конкретного клиента (по умолчанию выкл.): разрешает этому клиенту самому записываться без оплаченного остатка; глобального переключателя нет.
14. **Новый абонемент сначала гасит существующий долг** этого клиента (с явным предпросмотром в шторке оплаты).
15. **«Я оплатил» у клиента** только уведомляет тренера и не меняет баланс — оплату подтверждает тренер вручную.
16. **Анкету можно отложить**, но бот напоминает до первого занятия; тренер может нажать «Напомнить».
17. **Запрос на запись без абонемента** тренер подтверждает (занятие уйдёт в долг) или сразу оформляет как разовое.
18. **Фото прогресса**: на сервер уходит только размытая версия, оригинал не сохраняется нигде; при отсутствии найденного лица нужна явная ручная проверка.
19. **Отзывы**: в волне 2 тренер видит и отвечает; публично (волна 4, каталог и рейтинг) показываются только отзывы с согласием автора — авторов отзывов волны 2 спрашивают один раз при запуске каталога (Q53).
20. **Чек-ин по QR (В3)**: тренер показывает QR занятия, клиент сканирует его в Mini App (`showScanQrPopup`); на сайте — наоборот, клиент показывает QR записи.
21. **Делегирование (В3)**: помощник работает в своей зоне «Тренер» с переключателем контекста «Моё / <тренер>» в шапке «Расписания» и «Клиентов».
22. **Аварийный доступ админа** — с волны 1 (личные данные появляются уже в волне 1) как логируемая серверная функция с обязательной причиной и сроком, уведомляющая пользователя; **интерфейса в бете нет** (ADR 0007).
23. **Синхронизация с календарём** — календарный фид (`calendar_feed`, ICS) для каждой зоны в `/settings/calendar`; двусторонней синхронизации нет.
24. **Витрина `/trainers/[slug]`** публична с волны 1 (открывается без входа, с OG-превью); каталог `/trainers` — только с волны 4.
25. **Обратная связь** — шторка `/feedback` из «Профиля» обеих зон; админ превращает обращение в GitHub Issue вручную.
26. **Карточка клиента без аккаунта** — создаётся из «Клиенты → +»; переход к учётной записи подтверждает тренер в шторке «Это тот же клиент?», клиент слияние не подтверждает.
27. **Отклонённый на верификации тренер** продолжает работу в зоне «Тренер», баннер «Верификация отклонена» вместо «на проверке»; витрина `/trainers/[slug]` отдаёт «Тренер недоступен» (Q15).
28. **Тренер по реферальной ссылке тренера** (В3) сразу получает зону «Тренер» на тарифе Free (Q55).

## Дополнение: тарифы и права на функции (Q55–Q59, ADR 0014)

| Экран | Маршрут | Волна | Назначение | Ключевые элементы | Пустое состояние | Сущность |
|---|---|---|---|---|---|---|
| Мой тариф | `/settings/plan` | 1 | Что доступно пользователю | Текущий тариф (тренер и/или клиент), срок, что входит; унаследованные права по парам («Питание — от Pro-тренера Ивана»); «Запросить доступ» | — | Тариф, Право на функцию |
| Тарифы и выдачи (админ) | `/admin/plans` | 1 | Выдача Pro/Premium в бете | Поиск пользователя, «Выдать» (тариф, срок, причина), «Отозвать» (причина), история выдач, очередь заявок «Запросить доступ» | «Заявок нет» | Выдача тарифа |

**Состояние заблокированной функции** (все экраны): элемент виден, но приглушён; бейдж **Pro** или **Premium**; по тапу — шторка «Что даёт Pro/Premium» + кнопка «Запросить доступ» (в бете без цен). Лимит Free-тренера (3 клиента): на «Клиенты» — счётчик «3 из 3», кнопка «Добавить клиента» открывает ту же шторку.
