# Журнал решений DaFit

Итог grill-сессии 12–13 октября 2026 (Sam + Claude). Это первоисточник для PRD, ADR и тикетов.
Если документ противоречит этому журналу — прав журнал, пока решение явно не пересмотрено (тогда правим здесь и ссылаемся на ADR).

Рабочее название продукта: **DaFit** («Да фитнесу», отсылка к соучредителю Давиду). Репозиторий и техническое имя пока `fit`.

## 1. Продукт и рынок

| # | Решение |
|---|---|
| Q1 | Сначала **SaaS для персонального тренера (B2B2C)**: тренер переводит в продукт своих клиентов. Маркетплейс и соцсеть — позже (волна 4). |
| Q2 | Глобальное ядро вне РФ (текущий стек), отдельный контур данных для РФ — до официального запуска в РФ. |
| Q3 | Соучредитель — Давид (тренер). Бета: **5 тренеров × от 5 клиентов**, в основном РФ, офлайн и онлайн. |
| Q4 | Платформы: адаптивный веб (десктоп + мобильный браузер), Telegram Mini App, Telegram-бот. Нативные приложения — после беты. |
| Q5 | Языки RU + EN. По умолчанию RU. Автоопределение по языку устройства / Telegram `language_code`. |
| Q6 | Команда: Sam + Claude. Бюджет: ноль (только бесплатные тарифы). |
| Q7/Q45/Q46 | Название **DaFit** (предварительно). Совпадение с приложением «Da Fit» для смарт-часов в App Store известно, риск принят. |

## 2. Сроки и объём

| # | Решение |
|---|---|
| Q12/Q27/Q36 | Закрытая бета **24.11.2026**, цель — волны 1–3. **Черта качества 17.11**: всё, что не доведено до премиального уровня, переносится в декабрьскую волну, сырым не выкатывается. Приоритет переноса (что режем первым — последнее): волна 1 → питание → аналитика → группы → помощники/подмена → геймификация. То есть первой переносится геймификация, затем помощники/подмена, группы, аналитика, питание; волна 1 не режется (ADR 0005). |
| Q47 | Соцсеть, маркетплейс, карта — **волна 4** (январь–февраль 2027). Модель данных закладываем сразу. |

Состав волн — см. `docs/prd/`.

## 4. Люди, роли, доступ

| # | Решение |
|---|---|
| Q13/Q19 | Одна учётная запись, две зоны: **«Тренер»** и **«Клиент»** + роль админа (Sam, Давид, Claude). Переключатель зон в профиле; открывается последняя зона; переход из уведомления — сразу в нужную зону. |
| Q13/Q17 | Тренер может быть клиентом. У клиента сколько угодно тренеров; у каждой **пары** свои данные. Тренер видит только своё. |
| Q15 | Тренер — по **инвайту** (код/ссылка от админа) **или** по **реферальной ссылке тренера** (с волны 3). **Зона «Тренер» открывается сразу в обоих случаях** (пересмотрено Q55; одобрения админом для доступа нет). Верификация — отдельная ось (Q55): на проверке → верифицирован / отклонён. **Отклонённый** тренер продолжает работать со своими клиентами и может быть на Pro, но без значка, показа в каталоге/на карте и рейтингов (было O6, уточнено Q55). |
| Q15/Q16 | Ссылки для тренеров и для клиентов **разные**. Клиент приходит по ссылке или **QR** тренера (привязка без подтверждения) или по **ссылке на пробное занятие**. Без ссылки — экран «Введите код тренера». |
| O1 | Тренер может завести **карточку клиента без аккаунта**: ведёт по ней занятия, абонементы, оплаты, заметки, замеры; такому клиенту уведомления не отправляются. Когда человек позже приходит по ссылке клиента / QR этого тренера, тренер подтверждает совпадение, и карточка со всей историей **переходит** в его учётную запись (было O1). |
| Q18 | Помощники и подмена: модель + **интерфейс** (волна 3). AI-менеджер — после беты. Студии/залы — в модели, без реализации. |
| Q38 | Клиент управляет доступом каждого тренера к: питанию, замерам, фото, шагам, **своим тренировкам** (`workouts`, по умолчанию открыто — было O7) и **анкете**. По умолчанию открыто всё, **кроме фото и анкеты**. **Анкета** (здоровье) — чувствительные данные: тренер никогда не видит анкету не своего клиента, а в паре — только если клиент **явно разрешил** это при создании пары (отдельный шаг согласия, не тихое умолчание); решение меняется позже для каждого тренера (было O3). Фото — только по явному разрешению. Заметки тренера по умолчанию скрыты от клиента. |
| Q41 | Админ-панель: инвайты, верификация, пользователи, жалобы, отзывы/баги, метрики беты, журнал действий, **расширенная аналитика по всем тренерам и клиентам**. Личные данные клиентов (питание, фото, замеры) админу не видны без логируемого аварийного доступа. |
| Q44 | Экспорт всех своих данных, удаление аккаунта (30 дней), отзыв доступа тренеру, бета-согласие при первом входе. |

## 5. Расписание, отмены, абонементы, деньги

| # | Решение |
|---|---|
| Q20 | Тренер назначает занятие (сразу подтверждено) **или** клиент записывается на слот (автоподтверждение при активном абонементе, иначе запрос). Офлайн (локация) / онлайн (ссылка). Групповые с лимитом. Повторяющиеся занятия. |
| Q21 | Отмена клиентом раньше дедлайна (по умолчанию 24 ч) — бесплатно; позже или неявка — **списание**; отмена тренером — никогда не списывается; перенос раньше дедлайна бесплатно; тренер может «простить» списание. Частичных списаний нет. История с причинами. |
| Q22/Q33 | Абонемент: N занятий, цена, валюта, срок (необязательно), заморозка; несколько одновременно; ручная отметка оплаты; разовые занятия. **Списание применяется всегда**: при нулевом остатке оно становится **долгом**. Тренер для **каждого клиента** решает, может ли тот сам записываться на слоты без оплаченного остатка («разрешить запись в долг», по умолчанию выключено) (было O2). **Ценовая сетка** (1/5/10/20) с ценой за занятие, выгодой в % и меткой «выгоднее всего». |
| Q9 | В бете денег через платформу нет: учёт абонементов + **ссылка тренера на оплату** (его СБП/самозанятый). |
| Q10 | Целевая модель: **двусторонний freemium** — тариф тренера (Free/Pro) и тариф клиента (Free/Premium) + комиссия за эквайринг позже (пересмотрено Q56–Q59, см. §11). |
| Q50 | Рефералка: акции тренера («приведи друга → +1 занятие») + бонусы тренерам за тренеров (месяц Pro / скидка на тариф). Бонусы начисляются **только после факта оплаты** (оплаченный абонемент/занятие клиента или купленный тариф тренера). |

## 6. Уведомления и коммуникация

| # | Решение |
|---|---|
| Q23/Q32 | Уведомления через бота. Клиенту: запись/отмена/перенос, напоминания, заканчивается абонемент, долг. Тренеру: новая запись/запрос, отмена, утренняя сводка, абонемент клиента заканчивается. Напоминания **настраиваемые**: до 3 штук из пресетов (1 день, 3 ч, 1 ч, 15 мин) или своё время; тренер задаёт значения по умолчанию для новых клиентов; время утренней сводки и тихие часы настраиваются; каждый тип отключается. |

## 7. Прогресс, тренировки, питание

| # | Решение |
|---|---|
| Q24/Q30/Q35 | Вес и замеры с графиками, единицы по локали; вводят тренер и клиент. **Фото прогресса** сразу: лицо размывается **на устройстве до загрузки**, ручная кисть, ракурсы, «до/после», приватное хранилище, временные ссылки. Прогресс по датам и **по количеству занятий** («вместе с…», «проведено N», серии, отметки 10/25/50/100). |
| Q25/Q34 | Лог тренировок: упражнения из **wger** (CC-BY-SA, с указанием авторства) + свои упражнения тренера; подходы/повторы/вес/время, прошлые результаты, рекорды, шаблоны; видео — ссылкой. |
| Q28 | Питание: **Open Food Facts** + сканер штрихкода, свои продукты/блюда, быстрый ввод ккал; **калькулятор нормы Миффлина — Сан Жеора**; тренер переопределяет норму клиента или группы; видит дневник, % попадания, комментирует день. |
| Q37 | Шаги/активность: ручной ввод + **iOS Shortcuts** (по личному токену). Android — вручную. HealthKit / Health Connect — с нативной оболочкой после беты. Вода и сон — вручную. |
| Q29 | **Группы-сегменты** тренера («Сброс веса», «Набор массы», свои): цель, шаблон нормы, аналитика, рассылка. Клиент сам выбирает цель (снижение веса / набор массы / поддержание). Марафоны — с геймификацией. |
| Q31 | Аналитика тренера: посещаемость, отмены/неявки, занятия и выручка, долги, заканчивающиеся абонементы, динамика веса/замеров, попадание в норму питания, клиенты под угрозой ухода, CSV, **финансы** (неделя/месяц/квартал/год, средняя цена тренировки, симулятор повышения цен, подсказки по ценам). Сравнение с рынком — когда наберётся достаточно тренеров (обезличенно). |

## 11. Монетизация и доступ

| # | Решение |
|---|---|
| Q55 | У тренера **три независимые оси**: **Доступ** (есть зона «Тренер» / нет) — открывается **сразу** по любому действующему инвайту (админа или реферальной ссылке тренера); **Верификация** (не подана / на проверке / подтверждена / отклонена) — влияет только на значок, показ в каталоге и на карте (волна 4), рейтинги и лидерборды; **Тариф** (Free / Pro). Отклонённая верификация не отнимает доступ и не мешает быть на Pro. |
| Q56 | **Тренер Free:** до **3 клиентов** (карточки без аккаунта тоже считаются), расписание, абонементы, напоминания, лог тренировок, прогресс. **Тренер Pro:** без лимита клиентов, аналитика и финансы с симулятором цен, группы и рассылки, питание клиентов с контролем тренера, помощники и подмена, реферальные акции, кастомизация витрины, экспорт CSV. После понижения тарифа сверх лимита: существующие клиенты остаются, добавлять новых нельзя. |
| Q57 | **Клиенту бесплатно всё, что связано с работой с тренером:** запись, абонементы, напоминания, тренировки и прогресс с тренером, анкета, базовый дневник питания. **Клиент Premium:** личная долгосрочная аналитика и тренды, расширенное питание (свои планы, микроэлементы, история без ограничений), фото прогресса без лимита (бесплатно — 1 комплект в месяц), тренировки без тренера (свои программы и шаблоны), позже AI-функции и привилегии в сообществе (волна 4). |
| Q58 | Клиенты **Pro-тренера** бесплатно получают те Premium-функции, которые тренер использует в работе с ними в этой паре: полное питание (если тренер ведёт питание), фото прогресса без лимита в этой паре, тренды по паре. Это **унаследованные права**: действуют, пока тренер на Pro и пара активна. |
| Q59 | В бете **тарифы и лимиты включены**, но **покупки нет**. Админ выдаёт Pro тренерам и Premium клиентам из админ-панели (срок — необязательно, причина обязательна); выдача и отзыв пишутся в журнал, пользователь получает уведомление в боте. Заблокированная функция показывает «Доступно в Pro/Premium» и кнопку «Запросить доступ» (заявка админам), без цен. **5 тренерам беты Pro выдаётся при онбординге.** Покупка (провайдер, Telegram Stars/эквайринг, цены) — после беты. |
| — | Архитектура: единая система **прав на функции** с первого дня — тарифы, выдачи тарифов, одна проверка `has_entitlement(user, feature[, pair])` и в интерфейсе, и в базе (RLS/RPC; лимит клиентов проверяется в функциях создания пары и карточки клиента). См. ADR 0014. |
