# Журнал решений DaFit

Итог grill-сессии 12–13 октября 2026 (Рудольф и Claude). Это первоисточник для PRD, ADR и тикетов.
Если документ противоречит этому журналу, прав журнал, пока решение явно не пересмотрено (тогда правим здесь и ссылаемся на ADR).

Рабочее название продукта: **DaFit** («Да фитнесу», отсылка к соучредителю Давиду). Репозиторий и техническое имя пока `fit`.

## 4. Люди, роли, доступ

| # | Решение |
|---|---|
| Q13/Q19 | Одна учётная запись, две зоны: **«Тренер»** и **«Клиент»** + роль админа (Рудольф, Давид, Claude). Переключатель зон в профиле; открывается последняя зона; переход из уведомления ведёт сразу в нужную зону. |
| Q13/Q17 | Тренер может быть клиентом. У клиента сколько угодно тренеров; у каждой **пары** свои данные. Тренер видит только своё. |
| Q15 | Тренер приходит по **инвайту** (код/ссылка от админа), по **реферальной ссылке тренера** (с волны 3) **или** по **ссылке своего клиента** «Пригласить своего тренера»: любой человек без зоны «Тренер» зовёт своего тренера, и тот входит без инвайта админа (решение владельца 20.10.2026, маркетинг 16; пару потом начинает сам клиент). **Зона «Тренер» открывается сразу во всех случаях** (пересмотрено Q55; одобрения админом для доступа нет). Верификация идёт по отдельной оси (Q55): на проверке → верифицирован / отклонён. **Отклонённый** тренер продолжает работать со своими клиентами и может быть на Pro, но без значка, публичной витрины, показа в каталоге/на карте и рейтингов (было O6, уточнено Q55 и Q60). |
| Q15/Q16 | Ссылки для тренеров и для клиентов **разные**. Клиент приходит по ссылке или **QR** тренера (привязка без подтверждения) или по **ссылке на пробное занятие**. Без ссылки открывается экран «Введите код тренера». |
| O1 | Тренер может завести **карточку клиента без аккаунта**: ведёт по ней занятия, абонементы, оплаты, заметки, замеры; такому клиенту уведомления не отправляются. Когда человек позже приходит по ссылке клиента / QR этого тренера, тренер подтверждает совпадение, и карточка со всей историей **переходит** в его учётную запись (было O1). |
| Q18 | Помощники и подмена: модель + **интерфейс** (волна 3). AI-менеджер после беты. Студии/залы есть в модели, без реализации. |
| Q38 | Клиент управляет доступом каждого тренера к: питанию, замерам, фото, шагам, **своим тренировкам** (`workouts`, по умолчанию открыто; было O7) и **анкете**. По умолчанию открыто всё, **кроме фото и анкеты**. **Анкета** (здоровье) содержит чувствительные данные: тренер никогда не видит анкету не своего клиента, а в паре видит её, только если клиент **явно разрешил** это при создании пары (отдельный шаг согласия, не тихое умолчание); решение меняется позже для каждого тренера (было O3). Фото открываются только по явному разрешению. Заметки тренера по умолчанию скрыты от клиента. |
| Q41 | Админ-панель: инвайты, верификация, пользователи, жалобы, отзывы/баги, метрики беты, журнал действий, **расширенная аналитика по всем тренерам и клиентам**. Личные данные клиентов (питание, фото, замеры) админу не видны без логируемого аварийного доступа. |
| Q44 | Экспорт всех своих данных, удаление аккаунта (30 дней), отзыв доступа тренеру, бета-согласие при первом входе. |

## 5. Расписание, отмены, абонементы, деньги

| # | Решение |
|---|---|
| Q20 | Тренер назначает занятие (сразу подтверждено) **или** клиент записывается на слот (автоподтверждение при активном абонементе, иначе запрос). Офлайн (локация) / онлайн (ссылка). Групповые с лимитом. Повторяющиеся занятия. |
| Q21 | Отмена клиентом раньше дедлайна (по умолчанию 24 ч) бесплатна; позже или неявка означает **списание**; отмена тренером никогда не списывается; перенос раньше дедлайна бесплатно; тренер может «простить» списание. Частичных списаний нет. История с причинами. |
| Q22/Q33 | Абонемент: N занятий, цена, валюта, срок (необязательно), заморозка; несколько одновременно; ручная отметка оплаты; разовые занятия. **Списание применяется всегда**: при нулевом остатке оно становится **долгом**. Тренер для **каждого клиента** решает, может ли тот сам записываться на слоты без оплаченного остатка («разрешить запись в долг», по умолчанию выключено) (было O2). Без разрешения у клиента может быть **одна** запись в долг за раз, и она приходит тренеру запросом; вторую система отклоняет. С разрешением клиент записывается в долг без подтверждения, но не больше числа одновременных записей, которое тренер задаёт в карточке клиента (по умолчанию 1). Неоплаченные записи: уже списанные в долг плюс будущие без абонемента, включая групповые и предложения из листа ожидания. Тренер записывает клиента в долг без ограничений и сам отмечает оплату (решение 18.10.2026). **Ценовая сетка** (1/5/10/20) с ценой за занятие, выгодой в % и меткой «выгоднее всего». |
| Q9 | В бете денег через платформу нет: учёт абонементов + **ссылка тренера на оплату** (его СБП/самозанятый). |
| Q10 | Целевая модель: **двусторонний freemium**: тариф тренера (Free/Pro) и тариф клиента (Free/Premium) + комиссия за эквайринг позже (пересмотрено Q56–Q59, см. §11). |
| Q50 | Рефералка: акции тренера («приведи друга → +1 занятие») + бонусы тренерам за тренеров (месяц Pro / скидка на тариф). Бонусы начисляются **только после факта оплаты** (оплаченный абонемент/занятие клиента или купленный тариф тренера). **В бете** (решение Рудольфа 20.10.2026, бэклог маркетинга 7) тариф не покупают, поэтому бонус тренеру за тренера положен, когда приглашённый активен 4 недели подряд (3+ проведённых занятия в каждой неделе от приглашения); месяц Pro выдаёт админ вручную в /admin/referral-bonuses, с началом после беты. |

Сравнение с рынком появится, когда наберётся достаточно тренеров (обезличенно). |

## 11. Монетизация и доступ

| # | Решение |
|---|---|
| Q55 | У тренера **три независимые оси**: **Доступ** (есть зона «Тренер» / нет) открывается **сразу** по любому действующему инвайту (админа или реферальной ссылке тренера); **Верификация** (не подана / на проверке / подтверждена / отклонена) влияет на значок, показ в каталоге и на карте (волна 4), рейтинги и лидерборды, а отказ ещё закрывает публичную витрину (дополнено Q60); **Тариф** (Free / Pro). Отклонённая верификация не отнимает доступ и не мешает быть на Pro. |
| Q56 | **Тренер Free:** до **3 клиентов** (карточки без аккаунта тоже считаются), расписание, абонементы, напоминания, лог тренировок, прогресс. **Тренер Pro:** без лимита клиентов, аналитика и финансы с симулятором цен, группы и рассылки, питание клиентов с контролем тренера, помощники и подмена, реферальные акции, кастомизация витрины, экспорт CSV. После понижения тарифа сверх лимита: существующие клиенты остаются, добавлять новых нельзя. |
| Q57 | **Клиенту бесплатно всё, что связано с работой с тренером:** запись, абонементы, напоминания, тренировки и прогресс с тренером, анкета, базовый дневник питания. **Клиент Premium:** личная долгосрочная аналитика и тренды, расширенное питание (свои планы, микроэлементы, история без ограничений), фото прогресса без лимита (бесплатно 1 комплект в месяц; что считается комплектом, решено в Q64), тренировки без тренера (свои программы и шаблоны; лог своих тренировок бесплатен, Q61), позже AI-функции и привилегии в сообществе (волна 4). |
| Q58 | Клиенты **Pro-тренера** бесплатно получают те Premium-функции, которые тренер использует в работе с ними в этой паре: полное питание (если тренер ведёт питание), фото прогресса без лимита (фото принадлежат клиенту, а не паре, поэтому такая пара снимает лимит целиком; уточнено Q64), тренды по паре. Это **унаследованные права**: действуют, пока тренер на Pro и пара живая, то есть пробная или активная (уточнено Q63). |
| Q59 | В бете **тарифы и лимиты включены**, но **покупки нет**. Админ выдаёт Pro тренерам и Premium клиентам из админ-панели (срок необязателен, причина обязательна); выдача и отзыв пишутся в журнал, пользователь получает уведомление в боте. Заблокированная функция показывает «Доступно в Pro/Premium» и кнопку «Запросить доступ» (заявка админам), без цен. **5 тренерам беты Pro выдаётся при онбординге.** Покупка (провайдер, Telegram Stars/эквайринг, цены) появится после беты. |
| без номера | Архитектура: единая система **прав на функции** с первого дня: тарифы, выдачи тарифов, одна проверка `has_entitlement(user, feature[, pair])` и в интерфейсе, и в базе (RLS/RPC; лимит клиентов проверяется в функциях создания пары и карточки клиента). См. ADR 0014. |

## 12. Решения по поручению владельца

Шесть вопросов, оставшихся после схемы волны 1, владелец продукта поручил решить Claude самостоятельно, как опытному продакт-оунеру. Claude решил их 15.10.2026 (Q60–Q65). В тот же день владелец поручил Claude вопрос о языке ответов бота (Q66). Владелец может пересмотреть любое решение здесь, тогда правим строку и ссылки на неё.

| # | Решение |
